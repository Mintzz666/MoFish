# 阶段 B：电脑 / 手机集中验收

测试入口：[MoFish B](https://mofish-phase-b.tibo-reset-notifier.workers.dev/)。这是独立 B 环境，A 的账号和存档不会自动迁入。
本轮自动化和部署已完成，B 尚待下列真机体验及用户接受。请用专门的 B 测试账号，先导出备份；不用真实 A 存档。
不需要等待 10–14 天：成长公式与进食去重已有 SQL/HTTP 证据，长期实际成长观察仍单独记录。

## 一次完成的顺序

1. **两端进入与恢复**：电脑和手机打开入口，登录同一 B 测试账号。电脑添加鱼和水草/石头，
   等待「已同步到云端」；手机刷新核对数量、鱼名、个体配色和造景。若注册邮件不能送达，记录原错误，
   不把默认 SMTP 的发信限制当作账号代码已通过；不要粘贴完整验证链接。
2. **造景和审美（约 5 分钟）**：手机点「布景」，拖动物件，并试转向、大小、方向微调、换造型、撤销、
   「放在这里」及「取消」。确认工具条能点到、不误投食；等待同步后刷新并在电脑核对。
   分别看日间/夜间、玻璃边缘与厚度、水体通透度、体素鱼/水草/石头/沉木；判断是否达到你想要的放松视觉。
3. **真实离线重连**：先正常加载页面和登录。手机关闭 Wi-Fi 与蜂窝网络，确认真的无网；移动一件造景并喂食，
   不清缓存。重新打开页面/回到前台应保留本机变化；恢复网络，等同步结束，再在电脑刷新确认造景与进食结果。
   短时喂食的成长增量很小，不要求肉眼立刻长大。若出现冲突，按下一步处理。
4. **双设备冲突与身份隔离**：两端先同步；手机断网改造景，同时电脑在线改同一鱼缸并等同步。
   手机联网后应显示冲突，不静默覆盖。选择「采用云端」后确认本机冲突备份可查看/导出。
   保存备份后退出，进入游客，再换第二个 B 测试账号；不应带入上一账号的鱼缸、未确认造景或进食队列。
   回原账号检查原档仍在。B 不复用 A 账号。
5. **持续运行与恢复（至少 10 分钟）**：手机实际运行 3D，切高/低画质、横竖屏、前后台/锁屏恢复，
   记录明显掉帧、发热、耗电或操作迟滞。切 2D 应继续使用同一存档，再切回 3D。
   如设备真实发生 WebGL 上下文丢失，核对自动 2D 保档；没有发生就标「未触发」，不强行宣称通过。
6. **音效**：有意点击水声开关，听音量、循环接缝及爆音；切后台、回来、静音/再开，确认无重复叠音。
   耳机/扬声器及系统静音模式会影响结果，记录实际组合。

电脑至少记录实际使用的 Safari/Chrome；如目标支持 Firefox，再补 Firefox。手机记录实际 iPhone/Safari
或 Android/Chrome，缺少的设备保持未测。桌面 Safari 冒烟和 Chromium 手机视口都不能替代手机真机。
