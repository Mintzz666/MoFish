二、产品方向和架构

- 名称始终 MoFish，定位轻松休息、共同养鱼的电子鱼缸。
- 保留游客、本地存档、离线能力、导入导出、无签到要求、无饿死惩罚。
- 保留独立 Cloudflare 静态入口 + Supabase Auth/Postgres；不依赖 ChatGPT 登录。
- 不引入 D1 第二权威数据库、自管常驻服务器、付费素材/服务或复杂账号系统。
- 优先复用现有模块，小步拆分领域状态、存储/同步与 renderer。Three.js 可用于 3D；
  不因实现 3D 重写已经验收的认证，不为使用框架而重写整个应用。
- 没有硬件支持时可选 2D；2D 与 3D 操作同一份领域存档，视觉切换不丢数据。

三、阶段 B：多人共享鱼缸和可靠协作

用户体验：拥有自己的鱼缸，邀请指定账号共同照料；可看清正在操作哪个缸、自己是什么角色。

必须实现：
1. 成员关系 owner/editor/viewer。owner 管理邀请、成员权限及撤销；editor 可做被授权的养鱼和造景操作；
   viewer 只读。普通 editor 不能邀请、提权、改 owner 或撤销其他成员。角色边界前后端一致。
2. 邀请定向到目标邮箱/账号、有有效期、可撤销、接受操作幂等；不能仅凭知道鱼缸 ID 或链接就获得权限。
   优先用可复制邀请链接和站内接受流程，无需新增自建发信系统；未登录先登录，已登录身份必须匹配目标。
   默认不做 owner 转移、公共大厅、聊天、支付或陌生人匹配。
3. 保留每个用户的个人缸，并能列出、切换自己拥有/加入的鱼缸；换缸、换号隔离缓存、操作队列和订阅。
4. 共享写入改为有明确语义的受控操作：改名、喂食、添加/移除鱼、水草与后续造景等，按实际支持的动作定义。
   使用唯一 operation_id，服务端事务授权、校验、去重、更新状态和 revision；不能把 A 的整缸快照保存
   无限制开放给多个成员，不能用客户端时间戳“最后写入覆盖”。不要给客户端直接写表权限绕过 RPC。
5. 相同 operation_id 重试只能产生一次副作用。去重键绑定鱼缸与操作者、核对相同 ID 的载荷一致性；
   明确去重记录的保留期和过期请求处理，不能删记录后让旧离线请求重新奖励。
   同字段互斥修改按 revision/实体前置条件返回可处理冲突；不同可合并操作不应互相抹掉。
6. 喂食与成长规则由服务端校验，不信任客户端奖励量或时钟；多人并发与重试不重复结算，成长仍上限 24 小时。
7. Supabase Realtime 通知已提交变化；数据库是权威来源。订阅授权、遗漏/乱序通知处理、重连取快照，
   不接受客户端广播作为权威数据。撤销后的旧会话下一次读写必须拒绝，不能收到后续受保护的数据；
   不承诺擦除成员在撤销前已合法下载到设备上的副本。
8. 离线操作落盘并提示未同步；重连重新确认权限与前置条件。已撤销、实体不存在或无法安全重放时，
   停止自动提交，保留本地备份并清楚提示，不静默丢弃或强制覆盖。旧账号迟到响应不能影响新账号/鱼缸。
9. 增加版本化迁移、必要约束、索引与 RLS。已有 A 迁移保持只读，个人旧缸升级不丢失。
   新旧客户端兼容策略必须写清：A 的旧 RPC 不得在共享缸上绕过新操作协议；
   如需阻止旧客户端写共享缸，应返回明确升级提示，同时保留个人缸和游客恢复路径。

B 验收至少包括：

四、阶段 C：完整视觉体验（原 C + D 合并）

目标是看得出提升、可长期使用的立体鱼缸，不只给 2D 图形加透视或把刚性鱼模型平移。

设计默认方向：
- 沿用当前 MoFish 温和、安静、留白、自然水色的气质；鱼缸为主角，工具少打扰。
- 重新整理电脑与手机布局、账户/共享/存档入口、喂食、选鱼、造景、状态提示与反馈。
- 核心操作在手机上可完成，不依赖 hover；交互可取消，加载、出错、离线/冲突状态清楚。
- 明确键盘操作和可读文字，对比度、触控命中区和减少动态效果可用。

先做可运行的设计/3D 原型与电脑、手机截图并提交，形成可反馈节点。

若收到用户方向反馈及时整合。涉及明显改变产品定位、付费依赖或破坏旧存档时再提出具体问题。
这将旧 C 的“先等设计方向反馈”改为有明确默认方向的原型检查点，不意味着设计已获最终验收。

必须实现：
1. 真正 Three.js/WebGL 3D 鱼缸、可辨识鱼体、相机、光照和景深层次；限制相机范围，
   桌面和触控可操作，避免穿模和丢失鱼缸。选择/点鱼/喂食不因 3D 坐标转换失效。
2. 鱼有连续身体到尾部的相位摆动、转弯弯曲、加减速、自然巡游、边界与基础障碍避让、追食。
   行为参数随鱼种或体型有差异；避免随机瞬移、频繁抖向、持续穿墙。无需昂贵流体或物理锁步。
3. 水面波动/光影、水下层次与适量焦散、随水摆动的水草；效果应能在目标设备稳定运行。
4. 可编辑并持久保存的造景最小闭环：水草、石块、沉木等少量可再分发物件；
   添加、选择、移动、旋转、删除；使用鱼缸本地/归一化坐标，校验边界和对象 ID，
   布局刷新、换设备和共享成员之间能恢复。不要扩展为无限素材商城或复杂地形编辑器。
5. 共享同步鱼的身份、名字、成长、喂食及持久布局；瞬时位置、尾摆、水波和相机由本机计算，
   不逐帧写数据库。editor 可造景，viewer 不可修改；多人改同一对象按 B 的事务和冲突协议处理。
6. 旧 version:1 存档可无损读取/升级；迁移前留备份，补充字段有合理默认，坏数据不能破坏原档。
   明确新增造景在 2D 的简化显示与导出/导入行为；不能要求用户清浏览器数据才能升级。
7. 2D/3D 切换及 WebGL 不可用、context lost 或资源加载失败时可恢复/降级，账号和存档仍可操作。
   后台暂停动画、减少动态效果、至少低/高画质档，清理旧场景 GPU 资源，防止切缸后持续涨内存。
8. 所有模型、贴图、字体、音效记录来源和许可证；可用自制程序化模型。
   新依赖与素材随构建可部署，遵守 CSP；不能临时关闭 TLS/CSP 或依赖不稳定远端素材来交差。
