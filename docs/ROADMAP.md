# MoFish 产品与技术路线

用户已明确提出：云端存档、多个设备共享进度、未来多人操作同一鱼缸、邮箱密码注册登录（不依赖 ChatGPT）、更好的页面设计、3D 鱼缸、真实鱼体运动/水面/水草与造景。Hermes 实现；Codex 指导、评审并在用户验收后执行版本管理。

本文件是开发顺序和验收依据，不表示这些功能已实现。版本号是建议目标；实际发布需用户验收。

## 推荐架构

- 网页入口：Cloudflare Workers Static Assets（静态请求优先，勿让所有资源都经过动态 Worker）。也可使用 Cloudflare Pages，首次由 Hermes 选择一种并记录，不并行维护两套。
- 邮箱密码认证：Supabase Auth。注册、验证邮箱、登录、退出、重置密码均走托管认证，不自行实现密码库。
- 游戏存档：Supabase Postgres，配合 Row Level Security（RLS）和事务/RPC。此阶段不再额外引入 D1，以免保存两份权威数据。
- 多人更新：后续使用 Supabase Realtime 作为变更通知，数据库是权威来源；通知丢失后重新获取快照。订阅必须授权。
- 用户注册页面不包含 ChatGPT/Google/GitHub OAuth。开发者登录云服务控制台与游戏用户登录是两件事。
- 现有私有 Sites 地址暂时保留用于旧版体验；在独立 Cloudflare 测试入口验证邮箱登录，不能用“在 ChatGPT 登录后再展示邮箱表单”冒充独立登录。
- 不需要一台常驻的自管主机。Mac mini 可作为开发/测试/备份设备；自托管是后备方案，需另做网络、HTTPS、备份和维护设计，本轮不开展。

这套服务有免费额度，适合原型与少量用户测试，不承诺永久零费用或生产可用性。Supabase 免费项目可能因闲置暂停；注册验证和密码重置邮件上线前需配置可用的 SMTP/发信服务，默认邮件通道不是面向任意用户的可靠生产发信服务。用户的实际电脑/手机网络必须验证前端、Auth 和数据库均可达，不能只测网页首页。

## 阶段与门槛

| 阶段 | 建议版本 | 实现范围 | 验收后才能进入 |
| --- | --- | --- | --- |
| A | v0.2.0 | 邮箱登录、单用户跨设备云存档、Cloudflare 独立入口 | 两台设备同账号恢复同缸；不同账号隔离；离线/冲突不丢档；无 ChatGPT 门槛 |
| B | v0.3.0 | 多用户共同养鱼、成员邀请/撤销、角色权限、变更通知 | 两个账号可协作；并发不覆盖；重复请求不重复奖励；撤销后不能继续访问 |
| C | v0.4.0 | 页面重设计与基础 3D 鱼缸 | 手机/电脑可操作；3D 与原存档兼容；设备不支持时可降级；账号与同步回归通过 |
| D | v0.5.0 | 鱼体摆动、真实转向/避障、水面光影、水草与造景 | 视觉效果与移动端帧率/电量平衡；效果可调；造景跨设备恢复一致 |

每阶段先交付可评审的开发分支、交接文档和验证结果。Codex 评审建议并不代替用户验收。Hermes 不自行合并 main、打版本标签或部署生产。

## A：身份与存档先于视觉升级

先小幅拆分现有状态、渲染、存储和身份模块，使当前 2D 渲染器继续工作；不要为了接云端先重写成 3D 或大型框架。

必要行为：

- 支持游客本地模式和邮箱/密码注册、验证、登录、退出、忘记密码与回调流程。
- 未配置云服务时仍能本地试玩，明确提示未连接云端；不能用 mock 登录宣称真实认证完成。
- 登录前本地存档与云端存档并存时，由用户选择导入为新缸/保留云端；不静默覆盖。
- 本地缓存按用户和鱼缸隔离。退出时从界面解除该账号数据，不把上一账号快照上传给下一账号。
- 明确“游客/离线/同步中/已同步/失败/冲突”状态。在线时对实质操作去抖写入；不要每 15 秒无变化地上传。
- 保存持久属性：鱼的 ID、名字、种类、成长、喂食记录，鱼缸布局及造景。每帧位置、相机和水波在本机计算，不逐帧上传。
- 使用数据库 revision 的原子条件更新；跨设备同时改动时返回冲突，不采用客户端时间戳的最后写入覆盖。保留未同步本地副本，允许用户明确选择/备份后重试。
- 云端离线成长结算使用服务端时间及记录，重复读取不重复结算；保留 24 小时上限。仍不饿死。
- 维持旧本地存档与 JSON 导入导出兼容。版本化存档结构，迁移前保留备份。

建议数据实体：`aquariums(id, owner_id, revision, state_version, state_json, updated_at, last_growth_at)`。A 阶段只有 owner 能读写；B 阶段再迁移加入 `aquarium_members`，不要为了多人提前做全部 UI。所有表与 RPC 都要落实授权、参数校验和并发控制，数据库约束不能只由前端模拟。

A 的必须验证项：

1. 真实或本地 Supabase 集成下完成注册、邮箱验证、密码登录、重置、退出及会话过期处理。
2. A 设备修改并同步后，B 设备登录同账号恢复名字、鱼种、成长和造景；刷新可恢复。
3. 账号乙尝试通过 SDK/REST/RPC 读取/修改账号甲鱼缸 ID 被拒绝，不能只隐藏前端菜单。
4. 两台设备对同一 revision 同时保存，只接受一个；另一台保留本地数据并提示冲突。
5. 断网修改、重连和重复保存不丢档，不重复结算成长。退出/换号不会串档。
6. 单测、构建、必要的真实数据库集成测试及手机/电脑浏览器测试。缺少云资源的项标记阻塞，mock 测试不等于端到端通过。

## B：共享鱼缸

- 用成员关系授权：owner / editor / viewer。邀请必须定向、可撤销、有有效期；未登录先完成邮箱登录。
- 喂食等操作用唯一 operation_id，数据库事务内去重并更新 revision；不同成员并发修改不能靠整缸快照覆盖。
- 敏感角色变更仅 owner 可做。服务端/RLS 负责授权；不能用知道房间号就能写入的公开频道。
- Realtime 只广播提交后的合法状态变化，不接受未经验证的客户端广播作为权威数据。断线重连取最新 revision。
- 分享的是鱼缸，不共享用户密码。成员撤销后，数据库和订阅访问都失效。
- 允许各设备鱼群瞬时位置不同；同步的是同一组鱼及长期状态。本阶段不实现逐帧锁步物理。

## C / D：视觉与运动

- C 先给出页面和交互设计，获得用户方向反馈，再实现 Three.js/WebGL 基础鱼缸、相机、光照和鱼模型。保留 2D 降级及低画质。
- 将 renderer 与领域状态分离，同一份存档可以被 2D 和 3D 读取。装饰物坐标使用归一化/鱼缸本地坐标，不保存屏幕像素。
- D 再改善鱼的骨骼/顶点摆动、身体到尾部的相位差、转弯弯曲、加减速、避障与追食；不能只是刚性模型平移。
- 添加可控水面波动、焦散/光影、水草摆动和分层造景。水的运动以视觉模拟为主，不先做昂贵的全流体求解。
- 约定测试设备后记录帧率、加载时间和资源大小；目标电脑约 60 FPS、普通手机约 30 FPS，可按实测调整。支持减少动态效果、后台暂停和质量档位，不为视觉效果牺牲移动端稳定性。
- 使用可再分发素材，记录模型、贴图和声音的来源与许可证。

## Hermes 与 Codex 的协作

- A 阶段建议分支：`hermes/cloud-auth-sync`。
- 开发任务的执行 prompt 在 `docs/HERMES-PHASE-A-PROMPT.md`。
- Hermes 每轮更新 `docs/HANDOFF.md`，给出已推送分支与完整 SHA。
- Codex 按 SHA 读取代码，评审账号隔离、冲突处理、旧存档、测试与部署配置；没有修复请求时默认只评审。
- 用户验收后 Codex 执行仓库 release hook；版本号可显式指定为本阶段目标。静态代码回退和数据库迁移回退不是同一操作，需要单独备份/恢复说明。
- 云账号创建、SMTP、域名和密钥需用户在对应控制台完成。Hermes 先完成可测试代码、迁移和配置说明，再提供最小配置清单；不能要求把秘密写入聊天或 GitHub。
