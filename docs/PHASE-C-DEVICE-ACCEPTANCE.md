# 集中真机验收：B 单人体感 + C 一起养鱼

入口：[MoFish C](https://mofish-phase-c.tibo-reset-notifier.workers.dev/)。请使用 QA 测试账号，先导出备份，
不要导入正式 A 存档。C 与 B 使用同一个独立 QA 后端，但浏览器缓存按站点隔离；A 的账号/存档不会自动迁入。
B 入口保留作旧版本对照。账号开启 C 共享后请在 C 编辑，旧 B 的整缸覆盖保存会被服务端拒绝，以保护伙伴改动。

V0.2 测试版的自动化与部署见 [V0.2 验收记录](V0.2-ACCEPTANCE.md)。本轮无需用户参与；下面保留必须真人、实机或真实邮件参与的后续检查，
桌面浏览器手机视口和程序模拟断网均不能替代。建议准备电脑与手机、两个不同邮箱的 QA 账号；约 20–30 分钟。

## 按这个顺序做一次

1. **进入与邮箱**：电脑和手机打开 C。检查实际网络能否访问页面、登录和加载存档。用自己的测试邮箱检查注册验证/密码恢复邮件是否到达、点击后是否回到 C；不要把完整邮件链接发到聊天。若第二个邮箱收不到验证信，记录原错误；Supabase 默认邮件服务的收件人和额度限制仍可能需要自建 SMTP，再单独处理发信设置。
2. **同账号恢复与触控（约 5 分钟）**：两端先登录同一账号。电脑添鱼、改名、摆水草和石头，等同步完成；手机确认外观、数量、名字和位置。手机进入「布景」，拖动、转向、大小、换造型、方向微调、撤销、确认、取消；检查按钮能否点到、相机/投食是否误触。刷新后应恢复同一造型。新物件应有清楚高亮/定位圈；「完成布景」退出后取消高亮，待确认状态切回观赏也应保留并同步。
3. **邀请与协作**：电脑账号甲点「一起养鱼」，输入手机账号乙已验证的邮箱，选择「可编辑」，创建并复制代码给乙。乙先退出甲、登录乙，再在共享面板接受代码、进入甲的鱼缸。两端修改不同物件应都保留；鱼名、夜间和造景更新应互相看到。瞬时游动位置允许不同。邀请无需应用发送邮件，代码只能由指定邮箱接受。
4. **真实离线与冲突**：乙先正常打开共享缸，再关闭手机 Wi-Fi 与蜂窝网络。改一件造景并喂食，不清缓存；甲在线改另一件造景。乙恢复网络后，两份改动应都在。再试两端改同一物件，乙联网后应提示冲突；从顶部账号面板选择采用云端或保留自己的物件改动，检查备份可导出，伙伴其他新增内容不应消失。若离线中重新启动页面默认回到个人缸，可联网后从列表重进共享缸；共享队列按账号/鱼缸留存。
5. **角色与撤销**：甲在共享面板刷新成员，改乙为「仅观看」。乙应能看鱼，但不能投食、改名、添鱼或布景。甲移除乙，乙应回到自己的鱼缸，不能继续读取或上传甲的新变化。前台权限检查约 15 秒兜底；后台浏览器可能暂停计时，回前台后应重新核验。已缓存、截图或导出的历史内容无法远程抹除。
6. **换号与个人缸**：乙返回个人缸后检查自己的鱼、造景没被甲覆盖；退出看游客缸，换回甲核对原缸仍在。尝试无效/过期/已撤销邀请，错误提示应清楚且不会切错鱼缸。
7. **持续运行与声音（至少 10 分钟）**：手机 3D 持续运行，试「自动省电 / 省电 / 精致」、横竖屏、锁屏/前后台、2D 后再回 3D。记录卡顿、发热、耗电及恢复情况；如实际出现 WebGL 丢失，核对降级保档，没有发生记「未触发」。有意打开水声，听音量、循环接缝、爆音，试静音/再开、耳机/扬声器和回前台，无叠音。
8. **最终审美与手感**：分别看电脑/手机日夜效果、实体玻璃边缘、水体、体素鱼和前中后景；评估页面留白、对象侧栏/手机详情面板、共享弹窗滚动、按钮大小与反馈。补看2D日夜画风与鱼转向：身体应一直正立；轻触水面只看涟漪与回应，拖动/双指/取消手势不投食；用「喂一点」按钮或电脑空格明确投食。3D尝试「逗鱼」跟手/触按，观察是否自然。请指出具体不舒服的位置，不需要一口气重测已通过的后台规则。

9. **测试版本更新**：顶部应显示「V0.2 测试版」。有更新提示时先等同步完成，再点更新；未同步或冲突不应被自动刷新丢失。首次联网后打开「更多 → 存档」，等当前版本离线资源就绪；首次使用3D还需等3D缓存完成，再断网刷新。未下载过3D时能以2D继续，并提供联网重试入口。

## 直接回这个模板

```text
电脑：机型 / 系统 / 浏览器
手机：机型 / 系统 / 浏览器
网络：Wi-Fi / 蜂窝 / 原有代理；页面/Auth/鱼缸是否可达
邮件：注册验证 / C 回调 / 密码恢复（不要附令牌）
单人：同账号恢复 / 触控造景 / 刷新外观
协作：邀请接受 / 不同物件合并 / 同物件冲突与备份
权限：viewer 禁写 / 移除后返回个人 / 换号隔离
真实断网：保留 / 重连 / 问题
持续运行：10分钟流畅度 / 发热 / 前后台 / 2D / WebGL是否触发
声音：设备与结果
审美：接受 / 要改的具体位置
```

尚未实测的 iPhone/Android、Firefox、长期成长和性能组合继续标记未测；这些反馈和用户接受齐备后，
才判断 B/C 是否收口。本轮禁止 main 合并、标签和正式 release 继续有效。
