# 发给 Hermes：阶段 A 开发任务

将下面代码块中的内容作为新的任务消息发送给 MoFish 的 Hermes Profile。

```text
现在开始 MoFish 阶段 A：邮箱密码登录 + 单用户多设备云端存档。

仓库：https://github.com/Mintzz666/MoFish
你负责实现与测试；Codex 负责指导、评审和用户验收后的版本管理。

先读取最新版 AGENTS.md、README.md、docs/ROADMAP.md、
docs/HERMES-COLLABORATION.md、docs/HANDOFF.md。
检查现有工作区，保留任何未提交工作。在确认干净后获取最新 main，
建立或继续 hermes/cloud-auth-sync 分支；不要覆盖已有同名分支。
先简述实现计划，随后开始写代码，不要停在方案讨论。

技术方向：
- 独立 Cloudflare 网页入口，优先 Workers Static Assets；
  现有私有 Sites 地址保持原状。新入口不能要求 ChatGPT 登录。
- Supabase Auth 负责邮箱/密码注册、邮箱验证、登录、退出、重置密码。
  不使用 ChatGPT 或社交账号登录，不自己保存或验证密码。
- Supabase Postgres 保存游戏数据，RLS + 原子 revision 条件更新保护存档。
  先不额外引入 D1，不用家里的 Mac mini，不引入常驻服务器。
- 本阶段继续保留现有 2D 鱼缸，只做接入云端所需的模块拆分。
  多人共享、3D、真实水体运动属于后续阶段，这次不要同时实现。

必须实现：
1. 游客本地模式仍可玩；未配置云服务时正常降级并标明未连接云端。
2. 完整邮箱密码流程、真实错误提示、会话恢复和退出。
3. 本地旧存档迁移；首次登录遇到本地与云端两份存档时让用户选择，
   不静默覆盖，保留导入导出与备份。
4. 按账号和鱼缸隔离本地缓存，退出/换号不串档。
5. 显示游客、离线、同步中、已同步、失败和冲突状态。
6. 在线同步鱼的身份、名字、成长、喂食和造景，不同步每帧位置。
   写入去抖，只在有实际变更时保存，不做无限固定轮询。
7. 数据库原子检查 revision，冲突时保留未同步本地副本并提示处理；
   不能用客户端时间戳或“最后写入覆盖”冒充冲突解决。
8. 云端成长按服务端时间结算，最多 24 小时；重复请求不能重复奖励。
9. 真实数据权限：只能操作自己的鱼缸，RPC 也必须检查身份和参数；
   前端只隐藏按钮不算隔离。
10. 云端私有 API 不进入 Service Worker 公共缓存；保留静态资源离线能力。

交付物：
- 可运行代码、版本化数据库迁移、RLS/事务逻辑及必要测试。
- .env.example 仅放变量名与示例；区分允许进入前端的项目 URL/
  publishable key 与必须保密的 service-role/secret key。管理密钥不得进入前端。
- 配置说明：Cloudflare 静态发布、Supabase 项目、邮箱验证回调白名单、
  SMTP 发信配置、HTTPS、本地测试和部署前检查。
- 升级、备份与恢复说明；不能以删库作为默认回滚步骤。

验证至少包括：
- npm test、npm run build。
- 两个设备或独立浏览器上下文同账号恢复同一存档。
- 真实数据库下两账号的直接 REST/RPC 越权访问被拒绝。
- 两客户端相同 revision 并发保存冲突可控、旧数据不丢失。
- 离线修改后重连、退出换号、旧存档导入、重复成长结算。
- 电脑/手机页面与登录、重置密码回调流程。

云账号或凭据尚未准备时，继续完成可独立实现的代码、迁移、
本地测试和配置指南，再列出我需要在控制台完成的最小步骤。
不要索要在聊天中粘贴密码、API secret 或 SMTP 密钥。
未能真实验证的项目明确标记阻塞，不把 mock 通过写成云端联调成功。
不要擅自开通付费方案、修改线上站点、部署生产或删除数据。

结束时更新 docs/HANDOFF.md，审查并提交本轮改动，推送开发分支；
给我分支、完整 commit SHA、真实测试结果、剩余阻塞和请 Codex
重点检查的事项。未经我明确验收，不合并 main、不打标签、
不运行正式 release。完成这一阶段后等待评审，再开始多人或 3D。
```
